# OKH 감사부 AI 활용계획 통합 대시보드

감사부 AI 전환 과제의 진척 현황을 팀원이 함께 보고 편집하는 정적 웹 대시보드.
Firebase Realtime Database로 실시간 공유되며, 별도 로그인 없이 사용한다.

**두 개의 트랙으로 운영한다.**

| 트랙 | 대상 | 편집 | 화면 |
|---|---|---|---|
| **재편** | AI 에이전트 16개 · AI 과제 25건 (2026-08-18 재편안) | 진척률·착수상태를 여기서 수정 | 재편 대시보드 / AI 과제 25건 / AI 에이전트 16개 / 전환 매핑 80→25 / 제외 과제 12건 |
| **과거** | 원과제 80건 (기존 보고 체계) | 진척률 외 필드만 수정 | 대시보드 / 분기별 추진 일정 / 과제 목록 / AI 에이전트 / 변경 로그 |

원과제 80건 중 68건은 AI 과제 25건에 흡수됐고 12건은 AI 과제에서 제외됐다.
흡수된 68건은 상위 AI 과제의 진척률을 **안분**받으므로, 재편 트랙에서 과제 하나의
진척률을 올리면 과거 트랙 80건의 수치가 함께 움직인다. 기존 보고 체계를 버리지 않고
재편 성과를 반영하기 위한 구조다.

- 운영 URL: https://okh-audit-ai-project.vercel.app (Vercel — `main` 브랜치에 push하면 자동 배포)

로드 순서: `firebase.js`(module) → `data.js` → `data_v2.js` → `app.js` → `v2.js`.
`app.js`는 `data.js`에, `v2.js`는 `data_v2.js`와 `app.js`(`switchTab`·`goToTask`·`escapeHtml`·`showToast`)에
의존하므로 순서를 바꾸면 안 된다.

정적 자산에는 `?v=YYYYMMDDx` 캐시 버스터가 붙어 있다. **배포 시 이 값을 함께 올려야**
사용자 브라우저가 옛 JS/CSS를 물고 있지 않는다.

## 데이터 운영 규칙 — 어느 값이 이기는가

과제 필드는 두 부류로 나뉜다 (`app.js`의 `SYNC_ALWAYS` / `SYNC_AFTER_VERSION` 참고).

- **동적 필드** (`SYNC_ALWAYS`): 태스크·활용계획·착수상태·목표완료·공식완료일·진척률.
  항상 Firebase 값이 우선. 화면 편집으로 관리한다.
- **정적 필드** (`SYNC_AFTER_VERSION`): 담당자·우선순위·영역·에이전트·기대효과 등 나머지.
  기본은 `data.js`의 `RAW` 값이 우선이고, **`DATA_VERSION_TS` 이후에 화면에서 수정된 행만** Firebase 값이 반영된다.

따라서:

- 정적 필드를 일괄 변경할 때 → `data.js`의 `RAW`를 고쳐 커밋하고, **`DATA_VERSION_TS`를 현재 시각(epoch ms)으로 반드시 갱신**한다. 갱신하지 않으면 과거 Firebase 저장분이 새 코드 값을 도로 덮는다.
- 개별 과제의 일상적 수정 → 화면 편집 모달로 하면 된다 (동적/정적 모두 저장·공유됨).

재편 트랙(`data_v2.js` / `okh_audit/tasks_v2`)도 같은 규칙을 쓴다.
`v2.js`의 `V2_SYNC_ALWAYS`(진척률·착수상태·목표완료·비고)는 항상 원격이 우선,
`V2_SYNC_AFTER_VERSION`(과제명·구현·작동·산출물·담당자)은 `V2_VERSION_TS` 이후 수정분만 반영된다.

## 안분 규칙 — 재편 25건이 원과제 80건으로 내려가는 방식

`v2.js` 상단의 두 상수가 규칙 전부다. 보고 기준이 바뀌면 이 두 줄만 고치면 된다.

```js
const V2_PROGRESS_MODE = 'max';      // 'max' | 'inherit'
const V2_STATUS_MODE   = 'inherit';  // 'inherit' | 'max'
```

- **진척률 `max`** — 흡수된 원과제는 `max(자체 값, 상위 과제 값)`을 표시한다.
  흡수 덕분에 올라가기만 하고 내려가지 않는다.
  `'inherit'`로 바꾸면 상위 과제 값을 그대로 받아 재편안 엑셀과 1:1로 맞지만,
  자체 진척률이 상위 과제보다 높게 보고돼 있던 26건이 하락한다 (전체 평균 65% → 56%).
- **착수상태 `inherit`** — 상위 과제의 착수상태를 그대로 따른다.
  재편안에 미착수(설계안)로 적힌 과제19·20의 원과제도 미착수로 내려간다.

구현 지점:

- `window._v2ApplyProration(rows)` — 원과제 배열에 안분값을 씌운다.
  자체 값은 `_자체진척률` / `_자체착수상태`에 보존되므로 언제든 되돌릴 수 있다.
- `window._v2LegacyRollup(rows)` — 80건 집계 (`beforeAvg` / `linkedAvg` / `totalAvg`).
- Firebase에 저장할 때는 `app.js`의 `sanitizeForSave()`가 안분 파생값을 걷어내고
  **자체 값만** 올린다. 안분된 표시값이 원본으로 굳는 것을 막는 지점이다.
- 흡수된 원과제(68건)는 과거 트랙 편집 모달에서 진척률 슬라이더가 잠긴다.
  진척률 수정은 재편 트랙에서만 한다 (이중 관리 방지).

## 재편안 원본과의 차이 (의도된 보정 2건)

원본 엑셀 `OKH감사부_AI과제_재편안.xlsx`는 두 시트의 판정이 어긋난다.
흡수 합계 68건이 맞아떨어지는 **시트②(신과제 구성)를 기준**으로 확정했다.

| 원과제 | 시트① | 시트② | 채택 |
|---|---|---|---|
| #21 장부·전산 일치성 검증 | AX취소 | 과제24 흡수 | 과제24 |
| #50 부정 행위 상시 탐지 | 과제14 | 과제25 흡수 | 과제25 |

화면에서는 전환 매핑 탭의 해당 행에 보정 사유가 함께 표시된다 (`V2_LEGACY[].fix`).

## 주간 스냅샷 (진척 이력)

- **기록 주체는 브라우저다.** 금요일 12:00(KST) 이후 누군가 대시보드를 열면 `autoRecordWeekly()`가 그 주차 기록을 `okh_audit/weekly`에 저장한다 (금요일 당일 재접속 시 최신 데이터로 덮어씀, `anchorAt`은 금 12:00 고정).
- `functions/index.js`의 Cloud Function(`weeklySnapshot`, 금 12:00 스케줄)은 코드만 있고 **배포된 적이 없다** (2026-07 확인: 기존 기록의 `anchorAt`이 전부 브라우저 시그니처). 배포하려면 `cd functions && npm install && firebase deploy --only functions` — 배포 후에는 브라우저 기록 로직을 읽기 전용으로 바꾸는 걸 검토할 것 (이중 기록 방지 가드는 이미 있음).
- 금요일에 아무도 접속하지 않은 주는 기록이 빈다 (예: 2026_06_W1). Cloud Function을 배포하면 해결된다.
- 사이드바 "진척 이력"에서 주차를 클릭하면 그 주 스냅샷(읽기 전용)을 볼 수 있다.

## 로컬 개발

정적 사이트라 빌드 없음. 로컬에서 열어도 **운영 Firebase에 그대로 연결**되므로 주의.

```bash
python -m http.server 8000   # 후 http://localhost:8000
```

테스트 시 주의:
- 편집 모달 "저장", 에이전트 카드 ★ 클릭은 **운영 데이터를 실제로 변경**한다.
- 금요일 12:00 이후 페이지를 열면 주간 스냅샷이 기록될 수 있다.

## 알려진 이슈 / 검토 과제

- RTDB 보안 규칙이 열려 있음 (로그인 없음) — 규칙 파일(`database.rules.json`) 도입 검토.
- 저장소가 public — 내부 URL/IP가 포함되어 있으므로 private 전환 검토.
- 과거 트랙(`app.js`)의 테이블·로그 렌더링이 `innerHTML` 기반 — 입력값 escape 미적용.
  재편 트랙(`v2.js`)은 `escapeHtml()`을 거친다.
- 주간 스냅샷은 과거 트랙 80건만 기록한다. 재편 25건의 주차별 이력은 아직 없다.
- 다크 테마는 넣지 않았다. Chart.js 색상과 `app.js` 인라인 스타일에 하드코딩된 색이
  60여 개라 반쪽짜리가 되기 때문. 도입하려면 그 색들을 먼저 CSS 변수로 걷어내야 한다.
